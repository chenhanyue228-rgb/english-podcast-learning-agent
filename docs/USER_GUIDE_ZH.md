# 英语音频学习助手用户指南

English Audio Learning Agent（英语音频学习助手）使用 Codex（代码执行代理）
推进流程，使用本地 Python（本地程序运行环境）完成确定性处理，并把学习结果
保存到 Notion（知识管理工具）。

普通用户不需要寻找项目目录，不需要输入 `cd`，不需要手动创建虚拟环境，也不
需要手动执行主要处理命令。

## 开始前准备

需要：

- 英语音频学习助手技能。
- 完整本地项目。
- 一个可使用的 Notion 工作空间。
- 用户自己创建的 Notion 内部连接。
- Notion 内部连接的访问密钥。
- 一个名为“英语音频学习助手”的空白 Notion 页面。
- 项目内 Python 运行环境；Codex 会负责定位和准备。

不需要：

- OpenAI API 密钥。
- Codex 的 Notion 插件。
- 手动创建四个数据库或编辑本地配置文件。

可选：

- Codex 的 Notion 插件，仅用于搜索、读取或辅助查看已有内容。

Notion 插件仅是可选的搜索、读取和辅助查看工具。插件授权不会传递给本地
Python，也不能代替第一次设置。数据库创建、验证和学习内容写入始终由本地
Python 通过用户自己的 Notion 内部连接完成，不存在第二条插件写入路径。

## 1. 安装阶段

第一次安装时，把下面这段话发送给 Codex：

```text
请从下面的项目安装英语音频学习助手：

https://github.com/chenhanyue228-rgb/english-podcast-learning-agent

安装成功后，请直接在当前对话中带我继续第一次设置。
```

GitHub（代码托管平台）仓库地址只在安装阶段提供一次。第一次设置和日常使用
不再需要仓库地址。

技能文件夹和完整本地项目是两个层次：

- `skill/` 让 Codex 识别英语音频学习助手及其执行规则。
- 完整项目包含 `scripts/`、`src/`、依赖和验证逻辑，是本地处理与 Notion
  写入所必需的运行环境。

只安装 `skill/` 不能代替完整本地项目。Codex 会自动获取或定位完整项目，
普通用户不需要知道项目文件夹路径。

正式运行目录默认使用 `~/EnglishAudioLearningAgent`。不要把正式项目放在
`Documents`、`Desktop` 或 `Downloads` 中；macOS 可能允许交互式运行，却
阻止后台 LaunchAgent 读取这些受保护目录。

## 2. 安装完成后的交接

安装完成后，Codex 应在当前对话中显示：

```text
英语音频学习助手已经安装完成。

现在可以在当前对话中继续第一次设置。

是否现在继续？
```

用户只需要回复：

```text
继续
```

当前对话优先继续，不强制新建对话，也不要求用户记住固定指令。

备用指令是：

```text
请使用英语音频学习助手，带我完成第一次设置。
```

只有当前对话暂时没有识别到新安装的技能时，才新建一个 Codex 对话并发送
备用指令。如果新对话仍未识别，才重启 Codex 后重试。

顺序始终是：

```text
当前对话继续
↓
新建对话作为第一次备用
↓
重启 Codex 作为第二次备用
```

## 3. Notion 第一次设置

第一次设置使用一条统一路径，不需要先判断自己“已有”还是“没有”连接。Codex
一次只显示一个操作，并等待当前回复后再继续。

### 步骤 1：打开开发者后台

打开 [Notion 开发者后台](https://www.notion.so/developers)，然后回复：

```text
开发者页面已打开
```

### 步骤 2：打开连接列表

点击开发者后台左侧栏的“连接”，然后回复：

```text
连接列表已打开
```

### 步骤 3：打开或创建连接

如果列表中已经有用于本项目的连接，直接打开它；名称不同也可以继续使用。
如果没有，请创建连接，名称建议填写“英语音频学习助手”，并选择保存学习资料的
工作空间。打开连接配置页面后回复：

```text
连接页面已打开
```

### 步骤 4：确认权限

在连接的“配置”页面确认以下内容权限已经开启：

- 读取内容
- 更新内容
- 插入内容

完成后回复：

```text
权限已确认
```

### 步骤 5：保存访问令牌

在同一个连接配置页面找到“访问令牌”，复制并安全保存。不要把令牌发送到聊天、
截图、公开文档或 GitHub。完成后回复：

```text
密钥已保存
```

### 步骤 6：打开 Notion 并创建页面

打开自己的 Notion 工作空间后回复：

```text
已打开 Notion
```

收到下一条提示后，在左侧栏点击“新建页面”，页面名称填写“英语音频学习助手”，
选择空白页面且不要手动添加数据库。完成后回复：

```text
页面已创建
```

### 步骤 7：添加集成

打开刚创建的页面，点击右上角“•••”，找到并点击“集成”，然后选择刚才打开或
创建的连接。如果连接名称不同，请选择为本项目使用的连接。完成后回复：

```text
集成已添加
```

开发者后台中的入口名称是“连接”；普通 Notion 页面中的授权入口名称是“集成”。

### 步骤 8：复制链接

点击页面右上角“共享”，再点击“复制链接”。请保留链接，不要发送到聊天。
完成后回复：

```text
链接已复制
```

只有收到这条回复后，Codex 才会准备本地环境并打开安全设置窗口。访问密钥和
刚复制的页面链接都只粘贴到这个本地窗口。

## 4. 本地安全设置

只有用户回复“链接已复制”后，Codex 才会：

1. 自动获取或定位完整项目。
2. 自动准备本地运行环境。
3. 自动打开本地安全设置窗口。

用户只在本地安全窗口粘贴：

- Notion 访问密钥。
- “英语音频学习助手”页面的完整链接。

访问密钥和页面链接都不发送到聊天。用户不需要截取页面编号，也不负责判断
数据库是否创建或验证成功。

用户不需要手动提取页面编号。

本地程序会验证访问密钥和页面权限，并自动创建和检查：

- Podcast Library（播客资料库）
- Expression Database（表达资料库）
- Vocabulary Database（词汇资料库）
- Weekly Review（每周复盘资料库，存放 Weekly Reflection 每周复盘内容）

新建的表达资料库会自动为“类别”“常见程度”和“复习状态”的选项设置语义
颜色，选项名称不会改变。已有表达资料库需要在 Notion 界面中只调整颜色；
不要删除、重建或重命名现有选项，也不要为了获得颜色而重建数据库。

如果安全窗口无法自动打开，Codex 会先尝试一键入口，再自动在访达中打开正确
位置，只要求用户双击“开始设置”。终端操作只能作为最后备用方式。

手动终端命令只属于最终备用方案。

## 5. 设置完成

成功后，Codex 应主动显示：

```text
第一次设置已经完成。

以下数据库已经创建并通过验证：

- 播客资料库
- 表达资料库
- 词汇资料库
- 每周复盘资料库

Weekly Review 默认每周六上午 10:00 自动生成。

是否使用默认时间？

你也可以回复：

- 使用默认时间
- 每周日晚上 8 点
- 每周五上午 9:30
- 暂时不开启
```

如果用户选择一个时间，Codex 一次只复述一个星期和时间，并等待用户明确回复
“确认启用”后，才配置并安装本地周计划。选择“暂时不开启”不会安装 Weekly
调度器，也不算设置失败。

周计划处理完成后，Codex 再邀请用户发送：

```text
请使用英语音频学习助手处理这个播客：

<粘贴播客链接>
```

## 6. 播客处理

用户只需要提供苹果播客单集链接、播客订阅源链接或本地音频文件。

Codex 自动完成：

1. 检查输入是否受支持。
2. 获取或读取音频。
3. 生成文字稿。
4. 创建分析请求。
5. 读取分析请求。
6. 生成符合格式要求的分析结果。
7. 使用本地 Python 验证结果。
8. 写入 Notion。
9. 返回最终 Notion 页面链接。

用户不需要复制完整后台处理步骤，也不需要手动运行主要流程命令。

## 8. 词汇自动同步

用户只需要在 Podcast 学习页面中准确选中文字，并设置粉色文字或粉色背景。
高亮什么，Vocabulary 中的词汇目标就是什么。系统不会根据上下文自动扩词，
也不会把相邻文字或整个表格单元格当成词汇目标。

自动流程：

```text
粉色高亮
↓
系统定时检查
↓
等待 90 秒，确认高亮不再变化
↓
Codex 生成词汇学习信息
↓
本地 Python 严格验证
↓
写入词汇资料库
```

用户不需要：

- 说“同步生词”
- 提供页面编号
- 运行命令
- 使用 Notion AI
- 进行二次审核

第一次启用自动同步时，系统只记录已经存在的高亮，不会把历史高亮全部补写。
之后新增的高亮才进入自动流程。重复运行不会创建重复词汇或重复正文。

## 9. 自动同步启停与诊断

本节命令只供 Codex 和开发者恢复使用，普通用户不需要手动执行。

查看状态：

```bash
./.venv/bin/python scripts/manage_automatic_vocabulary_scheduler.py status
```

安装并启动 60 秒定时检查：

```bash
./.venv/bin/python scripts/manage_automatic_vocabulary_scheduler.py install \
  --confirmation INSTALL_AUTOMATIC_VOCABULARY_LAUNCH_AGENT
```

停止自动检查：

```bash
./.venv/bin/python scripts/manage_automatic_vocabulary_scheduler.py uninstall \
  --confirmation UNINSTALL_AUTOMATIC_VOCABULARY_LAUNCH_AGENT
```

停止不会删除同步状态、学习数据或 Notion 记录。

需要诊断时，Codex 可以执行一次有限运行：

```bash
./.venv/bin/python scripts/run_automatic_vocabulary_once.py
```

不要把这个命令放进无限循环。正式自动运行由 bounded LaunchAgent 管理。

## 10. Weekly Review 自动生成

产品默认在当前 Mac 本地时区的每周六上午 10:00 运行。第一次设置完成后，
Codex 会先询问是否使用默认时间；用户也可以选择其他星期和时间，或回复
“暂时不开启”。

普通用户后续可以直接说：

- “把 Weekly Review 改到每周日上午 9 点”
- “暂停 Weekly Review”
- “恢复 Weekly Review”
- “Weekly Review 现在什么时候生成？”

Codex 负责解析、复述并执行对应的本地操作。安装、更改、暂停、恢复和卸载都
会先显示一个明确动作，并等待用户确认；只读状态查询不需要确认。普通用户
不需要打开终端、查找项目目录、编辑 `.env` 或管理 LaunchAgent。

每次后台运行只处理当前最新的一个到期周期并退出。电脑在计划时间休眠时，
恢复后允许补跑一次；已经成功的周期不会重复生成。学习数据不足时返回
`SKIPPED_INSUFFICIENT_DATA`，不会调用 Codex，也不会创建空白复盘页面。

以下命令只供 Codex 和开发者恢复使用：

```bash
./.venv/bin/python scripts/manage_weekly_reflection_scheduler.py status
./.venv/bin/python scripts/run_automatic_weekly_reflection_once.py
```

Weekly 自动调度已经合并并通过受保护的 Owner Acceptance。默认时间仍为
当前 Mac 本地时区的每周六上午 10:00；每位用户可以在第一次设置时确认默认
时间、选择自定义星期和时间，或暂时不开启。

## 11. 故障排查

只有自动流程无法继续时才使用本节。

### 恢复设置时页面不一致

第一次设置中断后，请继续使用最初创建的“英语音频学习助手”页面。即使页面
链接外观不同，只要是同一页面，系统也会正常继续。

如果误选另一个页面，系统会在创建或更新学习资料之前安全停止。此时请在本地
安全窗口重新粘贴原页面链接。

### 技能没有刷新

- 失败步骤：安装后的技能发现。
- 原因：当前对话尚未刷新技能列表。
- 权限：通常不涉及权限。
- 用户操作：先新建一个 Codex 对话并发送首次设置备用指令。
- 完成后回复：如果新对话仍未识别，再重启 Codex 并回复“已重启”。

### 数据库创建失败

- 失败步骤：Notion 第一次设置。
- 原因：页面没有添加集成、密钥无效或网络暂时不可用。
- 权限：通常涉及页面集成权限。
- 用户操作：确认项目连接已通过“集成”添加到“英语音频学习助手”页面，不要
  发送访问密钥。
- 完成后回复：“页面集成已确认，请重试设置。”

### 自动设置窗口没有打开

- 失败步骤：本地安全设置启动。
- 原因：当前 Codex 环境无法启动交互式窗口。
- 权限：可能需要批准打开本地文件。
- 用户操作：双击项目中的 `start_setup.command`；Codex 应先自动在访达中打开
  正确项目目录。
- 完成后回复：“设置窗口已完成”或提供不含密钥的错误信息。

### 音频处理失败

- 失败步骤：输入解析、音频获取或文字稿生成。
- 原因：链接类型不受支持、网络失败或音频不可读。
- 权限：本地文件可能需要读取权限。
- 用户操作：根据 Codex 指出的具体阶段重新提供链接或批准文件访问。
- 完成后回复：“可以重试”。

### 自动词汇同步没有运行

- 失败步骤：后台定时检查。
- 原因：LaunchAgent 未安装、未加载，或项目位于 macOS 受保护目录。
- 权限：不要把访问密钥发送到聊天，也不要把密钥写进调度配置。
- Codex 操作：先读取 scheduler status 和脱敏日志；如果出现文件访问拒绝，
  将完整运行环境准备在 `~/EnglishAudioLearningAgent` 后重新安装调度器。
- 用户操作：通常不需要；如果 macOS 明确弹出系统权限窗口，只确认与
  English Audio Learning Agent 本地运行有关的请求。
- 数据安全：恢复过程中保留同步状态，不删除 Vocabulary 记录，不扫描历史
  数据库组。
